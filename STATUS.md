# STATUS — Eurisco
Updated: 2026-09-19 (auto-distilled at restart)

## Purpose
Build, run and improve **Eurisco** — a self-hosted personal AI agent that lives in Telegram (bot interface "Kit", @eurisco_bot), runs 24/7 on the Raspberry Pi 5 (`rpicb5`), and is powered by Gemini. Its differentiator is **relationship intelligence**: a people CRM auto-built from email + calendar, passive learning after each conversation, and hot/active/cold follow-up tracking. This thread owns the codebase, the Pi deployment, and the home-network/AC/sensor integrations around it.

- **2026-08-02 — local model plan (not implemented).** Recommended **Qwen3-4B-Instruct Q4_K_M via Ollama on the home `server`** (i7-4790 + GTX 1050 Ti 4 GB — the only machine with a usable GPU; the Pi and the Oracle VM were rejected), wired in as `models.fast` while Gemini 2.5 Pro stays `models.smart`. Rationale: Qwen3 has the best small-model tool-calling; ~2.6 GB of 4 GB VRAM leaves room for KV cache; a 4B is good enough for heartbeat/reflect/briefing/simple queries (~80 % of calls) but not multi-tool synthesis. Requires an OpenAI-compatible client pointed at Ollama — a small patch to `src/agent/loop.ts`. `whisper.cpp`/faster-whisper `small` would fit alongside for transcription. Caveat: 1050 Ti is compute 6.1, near the CUDA cutoff — pin a working Ollama build.
- **AC control:** Tuya **cloud** API is the live path because the router blocks Tuya's local LAN protocol (port 6668). Long-term plan: replace Tuya entirely with the ESP8266/ESP32 + IR LED using `IRremoteESP8266`/`IRDaikinESP` (Daikin is well supported, no code learning needed). Control is deliberately **open-loop** (cron + plug-wattage verification, no room-temperature feedback); the sub-target setpoints in the profiles are the manual workaround.
- **Data flows:** sleep/climate/health arrive via iOS Shortcuts → ingest HTTP server on **port 3141** → `workspace/{sleep,climate}/` + Google Sheets. Strava syncs every 2 h to the "TCS 10K" sheet.
